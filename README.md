# Coastline Digital

Marketing site for Coastline Digital, a US-based software engineering and AI consulting company in San Diego that works with an international team of engineering professionals.

**Domain:** https://coastlinedigital.net · **Contact:** hello@coastlinedigital.net

The site is plain HTML, CSS, and JavaScript. Pages are generated by a small dependency-free Node script from content and components in `src/`, and the generated files are committed. Render publishes the repository root with no build step.

## Quick start

```bash
npm run build   # regenerate pages, styles.css, main.js, sitemap.xml, llms.txt
npm run check   # verify output is current; check metadata, headings, links, JSON-LD
npm run serve   # http://localhost:8000 (python3 http.server)
```

Node 18 or later is required for building. Nothing needs to be installed: there are no npm dependencies.

**Always run `npm run build` and commit the generated files after editing anything in `src/`.** `npm run check` (also `npm test`) fails if the committed output is stale.

## Content rules

- **Only publish verified facts.** Company details live in `src/site.mjs`. Do not add clients, testimonials, logos, metrics, certifications, team sizes, or outcomes unless they are approved and verifiable.
- **Engineers are international.** Never imply that all engineers are in the US.
- **Solution concepts stay labeled.** Entries in `src/content/solutions.mjs` with `type: "concept"` render an "Illustrative concept" badge and a disclaimer, and show "What we would measure" rather than results. To publish a real engagement, add an entry with `type: "case-study"` and approved `outcomes`. It renders with a "Client case study" badge and is listed first.
- **Technologies.** Capability categories in `src/content/company.mjs` have empty `tools` arrays. Add named technologies only after confirming they are organizational capabilities. Non-empty arrays render automatically.

## Design system

Tokens live in `src/styles/tokens.css`: colour, type scale, spacing, radius, elevation, and motion. Components reference semantic tokens only.

| Token | Value | Use |
|---|---|---|
| `--ink-900` | `#071a2b` | Dark sections, primary buttons |
| `--ink-950` | `#040c16` | Hero, CTA band, footer |
| `--paper-50` | `#fafaf8` | Page background |
| `--teal-500` | `#15afa5` | Brand accent from the logo (decorative) |
| `--teal-600` | `#0b7a73` | Accent text on light backgrounds (AA contrast) |
| `--teal-300` | `#5ed6cb` | Accent on dark backgrounds |
| `--blue-500` | `#2f5bea` | Focus rings, links, concept badges |

- **Type:** Instrument Sans for headings and Inter for body text, both self-hosted variable fonts (see `assets/fonts/README.md`), plus the system monospace font for labels.
- **Logos:** `assets/brand/coastline-logo.webp` and `coastline-logo-light.webp` are trimmed derivatives of `assets/brand/NewLogos/coastline-header-logo.png`. The light version recolors the navy to white for dark backgrounds.
- **Diagrams:** the hero architecture, solution diagrams, and partnership model are inline SVG and HTML generated from data in `src/components/diagrams.mjs`. Add a solution diagram by placing nodes on a 4×3 grid in `solutions.mjs`.
- **Motion:** reveal-on-scroll applies only to content below the fold. There are subtle background drift, SVG data-flow animations, and hover transitions. All of it respects `prefers-reduced-motion`. A persistent pause control sits in the hero and the footer.

## Forms

Two forms post natively to **FormSubmit** (`site.forms.endpoint`), which emails submissions to hello@coastlinedigital.net:

- **Project inquiry** (`/contact/`): name, work email, company, inquiry type, service interest, description, and optional timeline and budget. `?type=project|ai|team|partnership|other` and `?service=<service id>` preselect fields.
- **Partnership inquiry** (`/partnerships/#partner-inquiry`): name, work email, firm, role, partnership model, capabilities needed, description, website, and timing.

**Behavior**

- Client-side validation shows inline messages and an error summary, and moves focus to the summary.
- The email subject is composed from the inquiry type and company.
- The submit button shows a loading state; on return to `?sent=1` a success panel is shown and focused.
- Spam protection is a honeypot (`_honey`) plus FormSubmit's CAPTCHA (`_captcha=true`).
- Without JavaScript, the forms still submit, and validation falls back to FormSubmit.

**Before relying on production inquiries**

1. FormSubmit sends an activation email to hello@coastlinedigital.net on the first submission from the live domain. Submit both forms from https://coastlinedigital.net, activate, and confirm delivery and the return to `/contact/?sent=1` and `/partnerships/?sent=1`.
2. Optionally replace the email address in the endpoint with FormSubmit's random alias (shown in the activation email) to keep the address out of page source.

**Server-side validation:** FormSubmit performs its own spam filtering but does not enforce our field rules. If stricter server-side validation is required, move the endpoint to a provider with server-side rules, or to a small serverless handler. Only `site.forms.endpoint` and the CSP `form-action` need to change.

## Conversion tracking

`main.js` calls `track(event, props)` at the following points:

| Event | When |
|---|---|
| `cta_click` | Clicks on links with `data-track` |
| `form_start` | First focus in a form |
| `form_validation_error` | A submit attempt fails validation |
| `form_submit` | A valid form is submitted |
| `form_submitted` | The visitor returns with `?sent=1` |
| `capability_tab` | A capability tab is selected |
| `engagement_fit` | The engagement picker is used |

No analytics provider is configured, so nothing is sent anywhere. Events are only dispatched as `cd:track` DOM events.

To enable tracking:

1. Set `analytics.provider` in `src/site.mjs` to `"plausible"` or `"ga4"` and fill in its ID.
2. Add the provider's domains to `script-src` and `connect-src` in the `render.yaml` CSP.
3. Update the privacy policy in `src/pages/support.mjs`.
4. Rebuild.

Nothing loads until the visitor accepts the consent prompt, and the choice is remembered.

## SEO

- Every page has a unique title and description, a canonical URL, Open Graph and Twitter tags, and a single `h1`.
- BreadcrumbList data is on every subpage.
- Organization JSON-LD (verified facts only: name, email, logo, and San Diego address, with the United States as area served) is on the home and about pages.
- Each service page has Service data, the partnerships page has its own Service entry, the FAQ has FAQPage data, and the role page has JobPosting data.
- `sitemap.xml` is generated from page priorities; bump `SITE_UPDATED` in `scripts/build.mjs` for meaningful content changes.
- `llms.txt` and `ai.txt` are generated from the same content.

## Caching and security headers

The build fingerprints `styles.css` and `main.js` (`?v=<content hash>`), so manual cache busting is no longer needed. CSS, JS, and fonts are served `immutable`.

`render.yaml` also sets the following headers:

- A strict Content-Security-Policy: `'self'` only, with `form-action` allowing FormSubmit.
- HSTS
- Permissions-Policy
- `X-Content-Type-Options`, `X-Frame-Options`, and `Referrer-Policy`

The site has no inline scripts or style attributes.

## Deploying to Render

Deployment remains a Render Static Site using `render.yaml`: the publish directory is `.` and the build command is empty.

1. Run `npm run build && npm run check`, then commit.
2. Push. Render redeploys automatically (Blueprint) or from the dashboard.
3. After deploying, verify the redirects, the 404 page, the CSP (no console errors), and the form activation steps above.

`coastlinedigital.net` and `www.coastlinedigital.net` are configured as custom domains in Render.

## Security note

In November 2026, a malicious payload was removed from this repository. It consisted of `.vscode/tasks.json` auto-running `assets/brand/public/fonts/fa-brand-400.woff`, which was obfuscated JavaScript disguised as a font, with `task.allowAutomaticTasks` enabled. It had been introduced in merge commit `8743308`.

Do not add editor task configurations that run on folder open. Review merge commits, not only PR diffs.
